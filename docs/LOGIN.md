# 手机号登录

本阶段实现基于当前 KuGouMusicApi 文档和模块源码核对，使用模拟 HTTP 服务测试协议；用户已反馈手机号登录完成；重启恢复、过期续期、多账号等场景尚未逐项确认。没有复制上游源代码，也没有修改 API 仓库。

KuGouMusicApi 是当前开发阶段的临时中转服务，不是最终用户的部署要求。最终将请求实现迁移到 Android/Kotlin，保持手机号登录交互，移除普通用户的服务配置步骤；本阶段尚未实现直连。

## 界面

底部固定首页、搜索、音乐库、设置。首页仅保留两个推荐占位卡片。
设置顶部账号卡片进入独立登录页：+86 手机号、验证码、获取验证码与登录按钮；请求中禁用重复提交，验证码发送尝试间隔至少 60 秒，支持返回、滚动、键盘和深浅色。
登录成功返回设置，展示响应中的昵称及账号 ID；无昵称时使用“酷狗账号”占位称呼。当前使用通用账号图标，头像尚未接入。
退出登录经确认清除本机会话，不调用云端删除或修改接口。

## 接口决策

| 接口 | 调用时机与校验 |
| --- | --- |
| POST `/register/dev` | 首次发送验证码或登录前获取 dfid；检查 status 与非空 dfid，复用当前客户端设备 Cookie |
| POST `/captcha/sent` | 用户点击获取验证码；手机号放 JSON 请求体；检查业务 status |
| POST `/login/cellphone` | 用户提交验证码；手机号、验证码和可选 userid 放请求体；只有 status=1 且含有效 userid、非空 token 才认可成功 |
| POST `/user/verify` | 启动恢复账号或手动检查登录状态；valid=1 时保存播放 auth |
| POST `/login/token` | verify 明确返回 valid=0 时只尝试一次；拒绝则清除会话，成功校验账号 ID 未变化并保存新 token |

超时、HTTP 错误、无法识别的校验响应保留已保存的账号，标记为尚未验证并允许手动重试；不因此循环刷新登录。没有已验证的 token 过期时间字段，不编造定时刷新周期。刷新成功后旧播放 auth 作废，下次检查会话时重新获取。
`/song/auth`、`/song/url/auth` 属于具体歌曲播放鉴权，不是登录前置条件，本阶段不调用。

## 存储与隔离

- Android Keystore AES-GCM 密钥加密账号、服务地址及 Cookie，原子写入 noBackupFilesDir；普通 DataStore 仅存服务地址。
- 手机号和验证码仅存在 ViewModel 内存，返回或登录成功清除，不写 SavedStateHandle 或 Compose 保存状态。
- 不记录请求/响应正文和认证异常内容；关闭 HTTP 重定向，认证不进入 URL，不与音频 CDN 共享客户端。
- 服务地址变化时取消并等待旧任务结束、销毁旧客户端、清除与新地址不匹配的持久会话。当前尚无云端缓存或已接通的播放队列；接通这些功能时必须加入账号退出清理。
- 平台由服务部署配置决定，客户端不转换普通版/概念版 token。同一服务地址改变 `platform` 配置后应退出再登录。

## 当前限制与真实验收

仅支持 +86 手机号验证码。上游文档提供 userid 选择参数，但没有给出多账号列表结构：当前支持手动填写酷狗账号 ID，不猜测列表字段。自动账号列表选择需要脱敏真实响应后补齐。
响应映射采用源码可确认的字段，未知结构明确失败；未接入额外风控挑战。需要额外验证时提示先到酷狗完成，不尝试绕过。

真机验收步骤（由用户自行输入手机号和验证码，不收集凭据）：

1. 启动 API，在设置保存地址；进入手机号登录，发送验证码并提交。
2. 验证错误验证码、发送失败与断网的提示，确认未误报登录成功。
3. 成功后核对真实账号，重启 App 确认会话恢复；断网重启应显示未验证状态。
4. 手动检查登录状态、退出登录、切换服务地址，确认没有旧账号残留。
5. 如果有多账号或风控响应，只提供去除手机号、token、Cookie、secu_params、auth、设备标识后的字段结构以继续适配。

自动化测试只使用明确标记的合成响应与虚构凭据，不向真实账号发送短信或修改任何云端内容。
