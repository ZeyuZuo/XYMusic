# v0.1 产品范围与实施计划

状态：2026-09-17 讨论后形成的开发基线；本文件描述目标，不代表功能已实现。

## 产品原则

最终安装 APK 即可使用，客户端直连酷狗官方服务，无需用户部署后端。开发阶段允许暂用 KuGouMusicApi 中转联调，后续替换为自有 Kotlin 接口实现。

相遇音乐是使用酷狗账号云端数据的 Android 音乐客户端。参考 NeriPlayer 的简洁体验，页面以 Google Material 3 设计规范为准。首版目标是完成登录、发现音乐、播放、管理云端音乐库和浏览歌曲信息的完整流程。

- 我喜欢、自建歌单、收藏歌单均对应酷狗账号云端数据。云端为准，本地仅缓存；不另建一套本地收藏或本地歌单代替账号数据。
- 播放队列、播放进度、搜索历史及 App 设置可保存在本机。
- 功能以实际接口能力和账号权限为准。接口存在不代表已经联调成功，不编造歌曲数量、会员能力或写入结果。
- 工程已由用户在 Android Studio 编译运行。登录已获用户正常反馈，恢复与续期仍待完整验收，详见 [登录说明](LOGIN.md)；三类搜索和基础单曲播放已接通；播放范围与待验收场景见 [播放计划](PLAYBACK_PLAN.md)。

## 导航与页面

底部使用 Material 3 NavigationBar，固定四个入口：**首页、搜索、音乐库、设置**。设置从右上角迁移到底部，不再保留重复的全局设置按钮。迷你播放器位于底部导航上方，有当前歌曲时才显示。

设置页顶部放账号区：未登录显示“登录酷狗账号”；已登录显示头像、昵称和账号状态，提供退出登录。登录页面由此进入，成功后返回并更新账号数据。需要登录的操作也可引导至登录页，返回后保留原浏览位置；云端写操作不因登录完成而自动提交。

设置其余内容按需分组：播放音质、外观、关于。开发阶段暂时保留明确标注的联调服务地址，最终普通用户流程移除此配置。普通听歌页面不展示 API、token 等开发术语。

### 首页

内容区只有两张入口卡片：每日推荐、猜你喜欢。首版不加入轮播广告、排行榜、最近播放或其他内容模块。登录提示及加载/错误状态在对应入口内表达，不额外堆叠首页栏目。

**每日推荐**：点击进入列表，支持全部播放、单曲点播、喜欢和加入歌单。有多少展示多少，不设 30 首上限，不从其他来源补齐；存在分页时获取完整列表。点击一首按原始顺序将整个日推替换进播放队列，并播放点击位置；“下一首播放”只插入这一首。按账号和推荐日期缓存，跨天重新获取；当天再次进入复用结果，失败可重试。推荐日期优先采用服务端信息，不擅自假定跨时区刷新时间。

**猜你喜欢**：点击直接启动 FM 并进入播放页；若当前已在 FM 模式，回到现有播放页，不重置队列。剩余歌曲较少时自动补充，仅对自动推荐批次过滤重复项，不影响用户主动插入重复歌曲；下一首与“不喜欢”分开，只有明确选择“不喜欢”才发送该反馈。进入 FM 替换当前队列，不暂存或恢复旧队列，不提供 FM 清空队列操作。日推或普通歌单点歌替换列表并退出 FM；搜索点歌插入下一项并立即播放，保持 FM，允许重复；任何来源“下一首播放”只插入且保持原模式。获取失败保留当前可播内容并提供重试，不无限请求或无限跳歌。

FM 接口文档注明 `remain_songcnt > 4` 不返回推荐歌曲；补充请求需串行去重。`playtime` 单位、songid 映射、播放完成反馈时机在联调后确定。反馈仅覆盖 FM 推荐所需行为，不额外开启全量播放历史上报。

### 搜索

- 按 2026-09-17 用户补充要求，搜索支持歌曲、歌单、歌手三个分类；输入后点击搜索，分类下以紧凑列表展示，长标题和歌手信息允许换行。包含搜索历史、分页、清空输入、空结果和失败重试；当前搜索历史尚未实现。
- 歌曲支持点播、下一首播放、喜欢、加入歌单；歌单支持详情、播放和收藏。
- 取消或忽略过期查询结果，避免前一次搜索覆盖新结果。
- 专辑独立搜索及歌手、专辑完整主页后续再做；本阶段歌手只展示搜索结果。

### 音乐库

- 固定“我喜欢”入口，其余按自建歌单、收藏歌单分类展示。
- 支持歌单详情、分页读取、全部播放和单曲点播。
- 支持喜欢/取消喜欢、创建及删除自建歌单、向自建歌单添加/移除歌曲、收藏/取消收藏歌单；删除自建歌单需确认。
- 写操作检查业务返回后才报告成功，并刷新受影响的数据；失败保留上下文供重试。首版不做离线修改队列和复杂双向冲突合并。
- 不靠中文名称或假设的固定 ID 识别“我喜欢”；使用实测得到的系统歌单标志或可靠标识。
- 收藏接口可能涉及复制歌曲，必须核实其语义。不能在未验证前承诺自动跟随原作者更新，也不能自动覆盖用户已有歌单。

### 播放、详情和评论

点歌与队列变化以 2026-09-19 确认的 [播放列表核心交互规范](PLAYBACK_INTERACTIONS.md) 为准：独立歌曲插入并播放、歌单整表替换、下一首只插入、队列点选只切换；队列允许重复歌曲。

- 迷你播放器与完整播放页：封面、标题、歌手、播放/暂停、上下首、进度拖动、喜欢、队列及歌曲菜单。
- 普通队列支持顺序、随机和单曲循环；FM 使用自己的续播规则。
- 支持后台播放、通知栏与锁屏控制、耳机控制、音频焦点和耳机断开暂停。
- 保存上次队列与进度，重新打开只恢复状态，不自动出声。链接过期时重新解析，处理无权限、试听和不可播放。
- 基础音质选择以真实可用格式与账号权限为准，不提前承诺所有高解析格式。
- 歌词首版至少支持 LRC 滚动高亮和点击跳转；KRC 逐字歌词作为后续增强，不阻塞 v0.1。
- 歌曲详情展示歌名、歌手、专辑、封面、时长和当前音质；缺失字段不编造。
- 评论支持列表分页和楼层回复查看。评论排序/分类仅展示实测支持的选项，不预设热门/最新映射。
- 首版不做发表评论、回复、点赞，亦不做完整歌手/专辑主页。

## 登录与会话

登录是首个业务里程碑。建议先验证并实现手机号验证码登录；同手机号多个账号需允许选择。扫码作为候选后续方式，不要求首版同时实现全部登录渠道。普通版/概念版的选择及登录方式可用性在联调中确认，不能混用 token。

会话持久化使用 Android Keystore 保护密钥及加密存储；不把凭据混入普通设置、URL 或日志。请求使用受支持的请求体或认证头传递敏感数据。认证失效提示重新登录，不循环调用登录接口。

账号切换、退出或切换服务地址时隔离并清理旧会话、账号缓存和推荐状态，取消在途请求，防止旧响应回写到新账号；停止旧账号播放并清空其队列。不保留可继续使用的旧播放凭据。

## API 对照与联调重点

依据：`services/KuGouMusicApi/docs/README.md` 及对应 `module/` 实现；当前是源码核对，尚未完成真实账号联调。

| 能力 | 接口 | 首要验证 |
| --- | --- | --- |
| 设备与登录 | `/register/dev`、`/captcha/sent`、`/login/cellphone`、`/login/token` | 设备标识、会话刷新、平台和多账号响应 |
| 每日推荐 | `/everyday/recommend` | 实际数量、推荐日期、完整歌曲标识 |
| FM | `/personal/fm` | 续播参数、去重、反馈、时间单位 |
| 搜索 | `/search` | 认证要求、歌曲/歌单字段及分页 |
| 用户歌单 | `/user/playlist` | 系统喜欢歌单标志、自建/收藏分类 |
| 歌单读取 | `/playlist/detail`、`/playlist/track/all`、`/playlist/track/all/new` | global_collection_id 与 listid 的不同用途、分页 |
| 歌单写入 | `/playlist/add`、`/playlist/del`、`/playlist/tracks/add`、`/playlist/tracks/del` | 收藏语义、业务成功码、删除歌曲所需 fileid |
| 播放 | `/song/url` | URL 过期、音质、试听和权限；暂不使用加密兼容性未确认的新版接口 |
| 歌曲详情 | `/privilege/lite`、`/krm/audio` | hash、album_audio_id / mixsongid 关联 |
| 歌词 | `/search/lyric`、`/lyric` | id/accesskey、LRC 解码和时间轴 |
| 评论 | `/comment/music`、`/comment/floor` | mixsongid、楼层标识、分页和实际分类 |

联调先读数据。云端创建、删除、收藏等操作由用户在 App 中明确触发；自动化测试使用脱敏样本或模拟服务，不修改真实账号内容。

## Material 3 与代码约定

- 使用 Compose Material 3 标准组件与交互：NavigationBar、TopAppBar、Card、ListItem、BottomSheet、Dialog、Snackbar；颜色、字阶和形状通过统一主题管理。
- 支持浅色/深色；Android 12+ 可使用系统动态色，旧系统使用统一后备色。封面取色与复杂背景不作为首版门槛。
- 以标准排版、留白和清晰层级呈现音乐。首页两张卡片，音乐库使用易扫读的列表；不堆叠玻璃效果、渐变或装饰动画。
- 可点击区域至少 48dp；图标操作有读屏描述，选中状态不只依赖颜色。适配系统字体缩放、安全区域、键盘和系统返回。
- 页面切换保存滚动及输入状态；加载、空数据、错误、未登录分别表达，不把接口错误画成“没有歌曲”。
- 保持单个 app 模块，按职责组织文件。页面只消费状态和发送事件，ViewModel 管理页面状态，Repository 负责接口映射与云端数据，播放服务持有播放器。
- 使用直接、明确的代码。避免万能管理类、全局可变状态、层层转发的无意义接口和提前引入复杂框架；有实际复用需求才提取组件或抽象。
- NeriPlayer 按组件或独立策略复用，记录来源；不整份搬入耦合多音源、USB、同步的 PlayerManager。

## 实施顺序与完成条件

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1：导航与账号 | 四栏导航、设置账号区、服务连接、设备会话、登录和安全持久化 | 真机登录后显示真实账号，重启仍可用，退出后无旧账号数据 |
| 2：听歌闭环 | 歌曲搜索、映射、URL 解析、MediaController、队列和 LRC | 搜到的歌曲可播放、切歌、拖动、锁屏控制及查看歌词；错误可恢复 |
| 3：首页 | 两张卡片、每日推荐列表、FM 自动续播和反馈 | 每日推荐数量真实，FM 连续播放不重复补队列，切换普通播放正确 |
| 4：云端音乐库 | 我喜欢、自建/收藏歌单和写操作；歌单搜索 | 与官方账号数据一致，分页完整，写入成功可复查，失败不伪装成功 |
| 5：详情与收尾 | 歌曲信息、评论及回复浏览、音质、可访问性和状态统一 | 按以下清单验收，完成 v0.1 |

每阶段记录真实响应结构、必要测试和真机结果；涉及上游复用同步更新 THIRD_PARTY.md。

v0.1 验收覆盖：正常/失效会话，空歌单，多页列表，网络中断，播放链接过期，试听/无权限歌曲，FM 耗尽与失败，后台/锁屏，耳机拔出，音频焦点，进程重建，账号切换，浅深色和大字体。构建、单元测试、lint 通过后仍需真机验证。

不纳入首版：下载和离线曲库、本地独立歌单、桌面歌词、完整歌手/专辑页、社交发布、复杂音效、USB 独占、多音源、同步备份、历史日推和复杂动效。
