# 云端音乐库读取与播放实施计划

2026-09-26，开发分支：`feature/cloud-library`，从 `main` 的 `1bc9d0d` 创建。

当前已完成当前账号系统喜欢/自建歌单、空歌单和公开歌单的只读核对，证据见 [接口核对记录](CLOUD_LIBRARY_API_CHECK.md)。步骤 2 音乐库列表已实现，模拟器真实元数据展示已核对；详情与播放尚未接入。收藏非空、私有/无权限等分支仍待真实样本。各步分别记录代码实现、自动化验证、人工验收，不把计划或接口声明当成可用功能。

## 本轮目标与边界

读取当前酷狗账号的“我喜欢”、自建歌单、收藏歌单，展示详情与完整歌曲列表，接通全部播放、指定位置播放、下一首播放；搜索歌单结果复用详情页。

本轮不包含喜欢/取消喜欢、创建/删除歌单、添加/移除歌曲、收藏/取消收藏等云端写入，也不包含搜索历史、评论、音质选择或 Kotlin 直连。继续使用开发中转服务；不建立本地独立音乐库。首页和播放的待验收项继续保留记录。

## 已核对的接口边界

计划初建时精确读取了上游 `docs/README.md` 和下表对应 `module/*.js`。下表保留初查问题，2026-09-26 的真实只读结果与剩余限制以 [接口核对记录](CLOUD_LIBRARY_API_CHECK.md) 为准；未修改上游。

| 接口 | 源码与参数 | 待确认 |
| --- | --- | --- |
| `/user/playlist` | `user_playlist.js`；page/pagesize，默认 1/30 | 系统喜欢标志、自建/收藏分类、总数、结束条件、版本字段 |
| `/playlist/detail` | `playlist_detail.js`；ids 为 global_collection_id | 私有/公开歌单可见性、元数据结构、无权限响应 |
| `/playlist/track/all` | `playlist_track_all.js`；id 为 global_collection_id，page 转 begin_idx | 搜索公开歌单的完整读取、重复歌曲与不可播放条目 |
| `/playlist/track/all/new` | `playlist_track_all_new.js`；listid，page/pagesize，type | 账号云端歌单、喜欢歌单的 type 含义及分页；源码默认 300，文档默认 30 |

请求显式传入分页参数，不依赖默认值；不把 listid、global_collection_id、歌曲 hash、album_audio_id 和歌单条目标识混用。账号歌单优先验证新版接口，搜索公开歌单验证公开接口；不以未经验证的静默降级掩盖无权限或协议错误。

## 步骤 1：确认只读协议

1. 核对用户歌单、详情、歌曲页的实际响应；只进行必要的只读请求，不触发云端写操作。使用可用的开发登录会话，不导出凭据；没有可用会话时如实记录阻塞，不编造响应。
2. 优先覆盖“我喜欢”、一个自建歌单、一个收藏歌单和一个搜索公开歌单；有多页数据时核对相邻页。账号缺少某类数据时记录未验证，不为测试创建歌单。
3. 确认业务成功条件、喜欢歌单可靠标志、分类规则、两类歌单 ID、分页结束条件、数量语义、曲长单位及播放所需字段。核对空数据、无权限和失效歌单的区分。
4. 沿用已发现的中转缓存限制，对账号相关读取使用 bypass 头；验证实际请求方式，认证不进入 URL 或日志。
5. 在 `docs/CLOUD_LIBRARY_API_CHECK.md` 记录脱敏结构、字段类型和结论；不保存完整响应、凭据、真实账号/歌曲标识或播放地址。

完成条件：明确账号与公开歌单的读取路径、分页规则和模型映射依据。未确认分类保留为未知，不靠中文歌单名或固定 ID 猜“我喜欢”。尚未核实的协议不得标成已支持。

## 步骤 2：音乐库列表

1. 在 `domain/model/` 定义经步骤 1 确认的歌单元数据和引用；在 `data/library/` 实现 `LibraryRepository` 与响应映射，补充 `KuGouApi` 只读方法。
2. 在 `ui/library/` 新增 `LibraryViewModel`、`LibraryScreen`，替换现有占位页。固定“我喜欢”入口，展示自建/收藏分类；标识未确认时显示明确状态，不能打开猜测的歌单。
3. 支持未登录引导、首次加载、空列表、错误重试、手动刷新和分页加载。部分页失败保留已加载内容，并明确还有未完成页。
4. 复用 `AccountSessions`，按账号、会话归属和服务地址隔离状态。退出或切换时取消请求、清除旧数据，忽略迟到响应。首轮仅做会话内元数据缓存，不新增 Room 或磁盘缓存系统。

验证：协议映射、分页追加、业务失败不伪装为空、账号切换迟到结果失效；人工对照官方账号的分类与歌单数量。

完成条件：音乐库显示真实云端歌单，刷新和分页可恢复，浏览不改变播放队列。

## 步骤 3：歌单详情与歌曲分页

1. 新增 `PlaylistRepository`、`PlaylistViewModel`、`PlaylistScreen`，按已验证的歌单引用选择读取路径，复用现有 `Song` 领域模型。
2. 展示真实封面、名称、数量和歌曲；缺失信息不编造。保留原始顺序、重复歌曲和歌曲来源；不可播放条目需明确表示，不能悄悄过滤后仍声称列表完整。
3. 详情分页浏览、刷新和失败重试与当前播放分离。列表使用条目身份/位置区分重复歌曲，不以 hash 作为唯一 UI key。
4. 检查页码推进、重复页、总数变化和异常结束条件。读取期间云端变化导致无法确认完整性时提示重试，不无限请求。
5. 复用详情入口接通搜索歌单；以真实搜索结果字段确认 ID，不从显示文字推导。歌手结果仍保持现有范围。

验证：空歌单、多页、重复条目、无权限、缺字段、后续页失败、切换详情后的迟到响应；人工检查返回后的列表位置及正在播放歌曲不被打断。

完成条件：账号歌单和搜索公开歌单可进入详情，分页信息准确，错误不误报为空歌单。

## 步骤 4：完整列表播放

遵循 `PLAYBACK_INTERACTIONS.md`，复用现有 MediaController、播放服务及私有文件整表传输，不创建第二套队列。

1. “全部播放”取齐完整列表后从首项播放；点击一首取齐同一列表后从所点条目播放，保留源顺序和重复项，切到普通队列并退出 FM。
2. 已加载页不代表完整歌单。补齐期间显示可取消的准备状态，保留原播放；获取失败、空列表、无法确认完整性或超过现有 4 MiB 传输/快照边界时明确失败，不截断播放。
3. 所点位置按来源条目确定；若云端变化导致无法确定原条目，不以 hash 随意选中另一个重复项，提示刷新后重试。
4. “下一首播放”只插入当前歌曲，不取齐整表、不切歌，保持播放/暂停状态和 FM 类型。
5. 准备任务与新点播、队列操作、系统停止、账号切换协调失效，完整列表仍需通过服务端原子替换校验；旧请求不能覆盖新操作。

验证：点击第二个同 hash 条目、跨页整表替换、暂停时插入、FM 退出/保持规则、准备中取消或发起新操作、失败保留旧队列、超限明确失败。复用已有大队列测试，仅补新入口带来的行为测试。

完成条件：三个播放入口符合既定交互，整表获取与替换失败均不破坏现有播放。

## 步骤 5：集成验收与交付

每个有代码变化的步骤使用 JDK 17、SDK 35，在 `android/` 执行：

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

自动化使用脱敏结构或 MockWebServer，不依赖真实账号。文档步骤只检查内容和差异，不重复运行 Android 构建。测试、构建或设备条件不足时记录实际限制。

人工按顺序验证：

1. 登录后对照官方账号查看我喜欢、自建/收藏列表，验证刷新、多页和空列表。
2. 打开账号歌单与搜索公开歌单，检查数量、顺序、重复歌曲和返回位置。
3. 分别全部播放、点击中间歌曲、暂停时下一首播放，确认整表及选中位置。
4. FM 中下一首插入仍为 FM，歌单点播退出 FM；补歌迟到不能污染普通队列。
5. 完整列表准备中断网、取消或点播别的歌曲，旧播放/新操作不被覆盖；恢复后可重试。
6. 退出/切换账号或服务地址后没有旧歌单；重启播放队列仍按既有规则恢复为暂停。
7. 检查浅深色、大字体、读屏、触控范围，以及后台/锁屏切歌和歌词同步。

逐步更新 README 和本计划的实际结果，列出尚未验收内容。云端写操作另立计划，不因本轮读取通过而宣称云端管理已完成。

## 步骤 2 实现与验收（2026-09-26）

- `domain/model/CloudPlaylist.kt` 保留账号 listid/type 与独立的公开 collection ID。`data/library/` 负责只读请求、严格字段校验和不可变分页快照；`ui/library/` 的 ViewModel 消费 AccountSessions，Compose 只展示状态与发送浏览事件。没有新增 Gradle 模块、数据库或依赖。
- POST `/user/playlist` 显式 page/pagesize=30，带 bypass 头；认证仅由已有 CookieJar 管理。业务码、必需结构、整数范围、重复引用必须通过校验，不把错误当空数据。
- 固定“我喜欢”区域以 type=0/is_def=2 唯一匹配；多个候选或找不到时明确提示，并保留候选条目。自建/收藏按 type=0/1 分类，未知类型进入其他歌单；不按名称或 is_mine 分类，不丢弃空默认列表。收藏 type=1 仅按文档及合成样本适配，当前账号仍无真实非空样本。
- 当前会话内缓存已加载元数据，切换标签复用。手动刷新成功后替换首批，失败保留旧数据并标记可能过时；后续页失败保留已有列表并重试同一页。退出、账号/服务地址/退出代次变化取消在途请求并清空状态；旧响应不能回写。缓存不落盘。
- collect_count/album_count 都为零时，按已核对 list_count 确认完整性；非零时不猜求和关系，需要明确空结束页，并做计数下界检查。分页中总数/total_ver 变化、重复页明确报错并要求刷新。最多读取 200 页，每页最多 30 个歌单，超过上限明确失败，不能静默截断为“全部”。非零收藏与专辑计数路径仍需真实样本校验。
- 页面使用标准 Material 3 组件与资源文案，列表标题自然换行、装饰封面无重复读屏描述、按钮保持标准触控区域。保留标签切换时的滚动位置，账号变化重置列表状态。当前只展示歌单信息，没有假详情跳转或播放按钮，也没有云端写入口。

验证：JDK 17、SDK 35 下 `assembleDebug / testDebugUnitTest / lintDebug` 通过，115 项测试无失败（新增 15 项，使用合成数据/MockWebServer）；覆盖请求白名单、成功与空页区分、分类、分页计数/版本/重复页、分页重试、刷新取消旧页、账号/地址/退出代次隔离与不协作迟到响应。最终 lint 与安装结果见 README。

模拟器已安装调试包并打开音乐库：确认全部 4 个歌单、“我喜欢”446 首、两个自建歌单 326/15 首、默认空歌单 0 首、收藏区暂无歌单。此次未操作真实账号退出/切换、修改云端歌单或触发播放；不把这次展示检查当作完整设备验收。

人工继续验证：

1. 登录后打开音乐库，对照数量与分类；返回其他标签再进入应保留列表与滚动位置，点击刷新能重新加载。
2. 断网刷新应保留旧列表并提示不是最新数据；恢复网络后手动重试。冷启动断网不能显示为“没有歌单”。
3. 有超过 30 个歌单时加载更多；后续页失败保留前页，重试后不重复。当前真实账号仅 4 个歌单，此场景由模拟测试覆盖，设备上待合适账号验证。
4. 用户手动退出后旧列表清空；重新登录、切换账号或服务地址不出现旧数据。当前播放在浏览/刷新时不变化，退出则继续遵循现有停止播放规则。
5. 检查深色、大字体、旋转和读屏；歌单详情与播放将在步骤 3/4 接入，本步列表没有点击进入行为。
