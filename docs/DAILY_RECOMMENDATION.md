# 每日推荐：实现与验收

当前进度补充（2026-09-26）：日推、FM 播放及有限续播已实现，显式“不喜欢”已实现待真实验收；下文早期阶段记录中的“FM 未接入”只描述当时范围。自动播放反馈尚未接入，最新边界见 [FM 反馈说明](FM_FEEDBACK.md)。

2026-09-26，HOME_PLAN 阶段 1 已实现，真实列表交互与设备场景待人工验收。日推仍使用开发中转服务；FM 与云端音乐库未接通。

## 已实现

- 首页仍只有每日推荐和猜你喜欢两张卡片。未登录进入现有登录页，返回首页且不自动播放。已登录可进入独立日推列表；FM 显示尚未接入。
- 列表显示服务端推荐日期及实际歌曲数；日期缺失明确显示本机获取日期。支持加载、空结果、失败重试、刷新及返回。标题、歌手、专辑允许换行，图片请求不带 API 会话。
- 点击第 N 首：完整原序列表替换普通队列并选中 N；全部播放选中第一首；“下一首播放”仅插入该曲，保持现有播放与会话类型。浏览、刷新、返回和切换标签不发队列命令。
- 复用既有完整列表传输、会话校验和原子替换；保留重复歌曲，不去重、不限制 30 首。声明数量不等于实际数组长度、任一行异常或业务失败均拒绝整个响应，不把部分列表当成功。
- 日推请求为 POST `/everyday/recommend`，带 `X-Apicache-Bypass: 1` 跳过中转跨账号缓存；歌曲时长统一转为毫秒，播放时才解析音频地址。
- 单个原子文件（最多 4 MiB）只保存当前服务地址、会话归属、推荐日期、获取时间及 Song 元数据，不缓存原始 JSON、tracker_info、凭据或播放 URL。不引入数据库。
- 同一本机获取日复用结果，显式刷新可以重新请求；跨天进入、恢复前台或停留至本机次日时重新检查。服务端刷新时区尚未确认，因此显示原始服务端日期，不宣称本机午夜就是服务器换批时间。
- 刷新失败保留旧列表并标记“上次获取的推荐”；缓存仅供离线浏览，播放仍需联网。账号、退出和服务地址变化清除数据；请求代次、协程取消和 SessionStore 的会话锁共同阻止迟到结果回写。

会话观察从 `data/playback/PlaybackSessions` 移到 `data/auth/AccountSessions`，供播放、歌词和推荐复用；推荐 ViewModel 不持有播放器。

## 已做验证

- 经单独授权，通过一次性本机服务只读日推、搜索各一次：日期 `20260926`，声明/实际数量均为 30；同 hash 日推 `time_length=260` 与搜索 `Duration=260` 对应，按秒转换。没有提交反馈或修改云端数据。临时服务、端口转发、测试包及源码均已清理。
- `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` 通过，79 项测试全部成功。新增 11 项覆盖实测字段映射、75 首与重复项、完整性拒绝、坏行、非法时长、日期缺失/异常、跨天/时钟回拨、缓存白名单/隔离/损坏、POST 与 bypass 头。测试全部使用合成数据，不访问真实账号。
- 开发包已安装到模拟器；启动及首页结构检查通过：日推可点击，已登录 FM 禁用并显示尚未接入。未将首页检查描述为真实列表播放验收。
- 上游仓库未修改；原有未跟踪 `package-lock.json` 保留。

## 人工验收步骤

1. 保持开发联调服务可用。未登录点击日推，完成登录后应回首页且没有自动播放；再次点击进入列表，核对日期、实际条数和封面。
2. 先播放一首搜索结果；进入日推、滚动、刷新、返回、切换标签，当前歌曲及队列应保持。列表滚动位置应在返回后保留。
3. 点列表中间歌曲：队列应包含完整日推原序列表，选中正确位置；“全部播放”应从第一首开始，会话为普通列表。确认下一首与锁屏切歌正常，重复歌曲不丢失。
4. 播放或暂停时分别选择日推歌曲的“下一首播放”：只插入该曲，不立即切歌，不改变暂停状态、播放模式或普通/FM 类型。
5. 成功获取后断网再进入：同日缓存可浏览；手动刷新失败应保留列表并标记上次结果，不能清空当前队列。恢复网络重试应成功；重启 App 后缓存仍可浏览。
6. 跨过本机日期边界，再进入/恢复前台应重新获取；失败保留旧日期并标记上次结果。退出或切换账号/联调服务后，旧列表不得再次显示；请求中途切换也应如此。
7. 检查深色模式、大字体、旋转和读屏。无需人为改动真实云端歌单。空列表、超过 30 首、重复项与畸形协议目前由合成测试覆盖，真实接口按实际返回验收。

前置非空队列、强制停止恢复及完整日推设备交互仍待人工确认。通过这些验收后再进入 HOME_PLAN 阶段 2：FM 播放与有限续播。
